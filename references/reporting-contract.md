# 运营报表契约

源项目中可见的运营分析主题包括营业额、用户、订单、销量排名和业务数据导出。复用时，先定义数据契约，再开始写 SQL 或 Controller。

## 每项统计必须确定

| 要素 | 需要回答的问题 |
| --- | --- |
| 时间范围 | 是闭区间还是半开区间？按自然日、营业日还是时区？ |
| 口径 | 成功支付、已完成、已取消是否计入？退款如何处理？ |
| 维度 | 按天、门店、品类还是商品聚合？排序和并列规则是什么？ |
| 空数据 | 返回空序列、零值还是无数据标记？ |
| 性能 | 允许的最大日期跨度、分页/异步导出门槛和索引是什么？ |

## 导出流程

1. 校验权限、日期范围和导出规模。
2. 服务层生成结构化报表模型，而不是把格式化字符串散落在 Controller。
3. 专门的导出适配器负责模板、内容类型、文件名编码与响应流关闭。
4. 导出失败时写入可关联的 request ID；不要返回部分损坏的文件却标记成功。

`ClosedDateRange` 示例只处理基础日期边界。实际报表应额外明确时区、营业日切点和数据库查询的半开区间转换。
